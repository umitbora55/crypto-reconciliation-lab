# S9-F2 — required recovery work and evidence

The independent review of 0.7.0 found an acceptance-gate defect, not a failure of
its actual 21-case experiment. That genuine report contained 802 controls and five
observed process terminations. Its verifier nevertheless accepted 21 scenario names
with one generic check each, contradictory lost-ACK evidence, incomplete process
observations, and a real clean case that skipped financial evaluation.

## Reproduction and repair

`tests/test_admission_semantics.py` contains nine tests. The unchanged file first
ran against 0.7.0: the positive actual run passed, while 22 rejection subcases failed
because the old gate accepted them. Exit was 1. After repair the same nine tests
passed with exit 0. File SHA-256:
`dadd70eb0aa39db5e8ab26f8ea94aca231fa10db2aaa5d1f4371942d38eda4f7`.
The omitted-financial case invokes `_case` with a changed clean plan; it is not only
a mutation of a completed report. The old case saved zero runs and passed. The new
case rejects that plan before initialization or admission.

The new `admission-recovery-scope-v2.json` fixes each case's terminal state,
financial phase and variant, immutable input identities, exact required control
names and literal expectations. Dynamic values have explicit shapes and links.
The package contains an identical pinned resource for installed use. Neither build
nor verification derives this scope from a candidate report, discovery or execution.
The historical v1 scope and Stage 9 evidence remain unchanged.

The shared standard-library validator checks the runtime case, complete report and
release entry. Initial financial and interrupted readback controls receive explicit
phase prefixes; final names used by existing tests are retained. Required names are
unique and complete. `expected`, `actual` and `passed` are type-consistent: Python's
`True == 1` does not satisfy JSON evidence equality. Extra controls must have a
unique `extra:` name and internally consistent values; they cannot replace any
required control. The current inventory happens to retain 802 controls; the total
is not an acceptance rule.

Required observations include exact effect sequences and input hashes, receipt and
normalized-record links, immutable plans, saved run IDs and payload hashes, findings,
evidence and correction-table counts, and finite-feed responses. Durable response
outcome totals must agree with observed attempt history; the one unacknowledged
lost-ACK commit is explicitly accounted for. Complete, incomplete and blocked feed
claims have different constraints. Malformed or missing nested evidence cannot be
replaced by a top-level PASS.

Precommit cases retain complete before/after core and run-table fingerprints and
an eight-record prefix. Lost ACK retains the ninth commit, its original receipt and
result, then one replay attempt. `save_run` compares all five related tables before
and after the interruption, retains the old payload hash, and links final table
counts to both saved run payloads. These are content-consistency checks, not proof
that an arbitrary third party cannot fabricate a whole internally consistent report.

Every process observation binds READY, PID, requested/observed barrier, RESULT or
UNKNOWN, termination and join. Actual writer settings are collected from the Store
connection used by the parent operation and from each child's READY, BARRIER and
RESULT connection. Readback settings are separately named. No PRAGMA value is
changed. Parent writer operations and process identity are required independently
of the report's claims.

An independent follow-up probe found three omissions in the first new gate's
parent-writer provenance checks. `tests/test_admission_provenance.py` adds three
tests: four rejection subcases failed before the narrow inventory/PID repair, then
passed unchanged. File SHA-256:
`f45c8124914aeba3a44c738eb6b06ec942dee0479b6a1d39ef5ac3f18607525c`.
The same external 13-mutation probe subsequently rejected every counterexample
while accepting the actual 21-case report. Its earlier accepted cases are retained.

## Final no-AI gate exposed a bounded-writer false negative

The first full source/installed470-test release verification and373-file financial
matrix passed. Its separate no-AI recovery then reported two FAILED writer cases.
The actual child processes exited0; all transport/financial readback checks passed.
A bounded contender returned `RETRYABLE_BUSY`, no ACK, no durable attempt, and an
explicitly unknown cursor/block state. The newly strict semantic gate had required
a boolean block flag and integer cursor even for that legitimate intermediate state.
This was a false negative in the new verifier, not an admission or financial defect.
The first candidate's full PASS, core FAIL, distributions and freeze are preserved.

`test_admission_busy_evidence.py` adds two tests. Its valid bounded-busy fixture
initially produced a real RED error (exit1); the unchanged file then passed (exit0).
Its negative subcases retain missing/partial UNKNOWN, ACK, durability, attempt-ID,
wrong-outcome, completed-state and incomplete-final-inventory rejections.
The compact report now retains `state_observation`. Only a writer-scenario
INCOMPLETE response with explicit UNKNOWN, paired null prefix/block, and a
RETRYABLE_BUSY non-ACK/non-durable result with no attempt may use that representation.
No unknown intermediate state can replace the required complete final inventory,
joined writers, finite retry budget or financial evidence. The historical delivery
protocol and its behavior remain unchanged.

The revised fixed scope explicitly documents this bounded intermediate allowance.
The original nine semantic and three provenance regression files remain unchanged
and pass again. Revised final source/installed/no-AI/CI checks are distinct records;
no first-candidate failure is overwritten or relabelled as final success.
