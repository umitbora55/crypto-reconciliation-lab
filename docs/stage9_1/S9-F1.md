# S9-F1 — durable malformed-frame diagnostics

The user-supplied independent review reproduced this defect against commit
`16f54490635ee37bbb91eeece18a55f7316f13f2` (0.7.0). Its results are external
starting evidence, not execution by this maintenance task. The same defect was
also exercised by new regression tests before changing the runtime.

## Trigger and narrow repair

The middle line in a three-line file contains ASCII JSON escape bytes:

```json
{"record":{"\ud800":1,"\ud800":2},"received_at":null}
```

The JSON duplicate-key hook rejects this input. Previously, concatenating the
decoded key into the diagnostic produced a Python string with a lone surrogate.
Writing that diagnostic to SQLite TEXT raised `UnicodeEncodeError`; the terminal
rejection and attempt rolled back. The first valid line remained committed, but
the file repeatedly stopped before the third line.

`_envelope.unique` now quotes the key with `json.dumps(key, ensure_ascii=True)`.
This produces a safe, explicit JSON string literal for all key text, including
surrogates, control characters and valid Unicode. Duplicate-key rejection remains
enabled. This changes only the diagnostic representation: exact input BLOB bytes,
payload hash, stream/sequence, declared plan, financial normalizer and transaction
boundaries are unchanged. No Unicode normalization, ignored characters, silent
record skipping or fabricated financial receipt is introduced.

## Limits

COMPLETE here means all three transport sequences reached a durable disposition.
It does not mean the malformed financial input was accepted or economic scope is
complete. The CLI intentionally exits 1 for terminal rejected input. This repair
does not broaden the historical financial parser's accepted input domain or alter
the financial/review/triage v1 contracts.
