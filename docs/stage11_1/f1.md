# S11-F1: original acceptance causality

The original verifier checked the sole COMMITTED attempt and its matching
original authorization link, but did not check whether an earlier attempt
already referenced that effect. A controlled capture could relabel the genuine
later replay as COMMITTED, move the original link and reuse an already pinned
valid policy. Its internal relationships were impossible despite valid signed
materials and a deliberately refreshed operator observation pin.

This is a semantic check of a deliberately repinned synthetic capture. It is
not an operator-pin bypass, a signature forgery or a claim about run-creation
authorization. `NOT_RECORDED` and `NOT_PERFORMED` remain unchanged.

## Narrow repair

For each selected effect position, the verifier identifies its sole COMMITTED
attempt using existing relationship checks. Every attempt that references that
effect must have a persistent attempt ID at least as large as the original
COMMITTED ID. A later effect-referencing attempt must also link to a decision
whose persistent decision ID is greater than the original COMMITTED attempt's
decision ID. Comparisons stay within their respective SQL identity namespaces.
Contradictions return `DELIVERY_CAUSALITY`, exit 2.

The runtime inserts the effect, its COMMITTED attempt, authorization decision and
original link in one transaction. An effect reference cannot predate that
transaction. The check does not require COMMITTED to be the first attempt: an
earlier GAP without any effect reference is accepted. It does not order by JSON
array position or trust `observed_at`, require unrelated stream history, alter
runtime/schema behavior, or recompute financial results. Known contradictions
still take precedence over missing signed snapshot material.
