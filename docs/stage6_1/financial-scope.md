This identity was supplied by the independent review and matched the actual local 0.6.0 baseline.

`release_financial_scope.py` records that identity outside the reference. It also records the canonical document SHA-256 `b7329cb6c0b0cc95afe00de012f3f52e81cb2333a5ba0d17dba4bb65272d425d`, measured once from the reviewed document during implementation. Normal build and verification never regenerate either expected identity. These values detect accidental changes to the reviewed baseline; they are not a cryptographic third-party authenticity certificate.

`load_financial_reference(path)` requires a regular file with the exact original raw bytes. It rejects malformed JSON and duplicate keys. Structural validation requires `financial-reference-v1`, baseline package 0.5.1, rule `stage2-v2`, integer schema 3, and genuine JSON types. It checks 325 matrix files, 12 Stage 1 files and 36 Stage 2 files, totaling 373. The matrix scope is 69 cases / 162 evaluations, seeds 11/29/47, 100 events and six investors, with the ten explicit named error counters. Every report name is a safe relative JSON/Markdown path; every proof has a positive integer size and a lowercase 64-character SHA-256. The fixed canonical identity binds the complete names, hashes and sizes, including same-count substitutions or cross-group exchanges.

Both supplied-source and automatic-build release routes validate the reference before build, environment creation, installation, tests or reproduction. The core profile validates the complete reference even though its matrix execution remains `NOT_RUN`. The build route validates after the existing document-link boundary and before external build commands, preserving the old canonical-output fixture's stopping point.

`compare_required_reports(directory, reference, group)` revalidates the full in-memory reference before each comparison. It checks the actual output inventory against the mandatory group and hashes every required file. Missing output, unknown extra report names, symlinks, renamed files or one changed byte fail. It reports `expected_count`, `compared_count`, the complete compared file/hash/size inventory, a group inventory SHA and the fixed reference identity. There is no zero-file successful scope. `validate_matrix_result` requires exactly the ten named counters with integer zero values and integer 162 evaluations.

The existing producers also write configuration files and summaries. These are explicitly separate from saved financial reports: Stage 1 allows four named scenario `config.json` files plus `summary.json` and `summary.md`; Stage 2 allows five named scenario configuration files plus the two summaries. The matrix producer additionally writes `correctness.json` and `correctness.md`, both explicitly allowed as ancillary output. The helper records the actual ancillary names in `excluded_producer_ancillary_files`; they never satisfy or enlarge the 12/36/325 required report sets.
