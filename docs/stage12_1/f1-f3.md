# Export namespace and recorded-input boundary repairs

These are narrow 0.10.1 repairs to S12-F1 and S12-F3. They preserve schema 6,
stage2-v2, raw financial payloads, recorded-execution-v1 and existing correct
context bytes. The independent review supplied the initial examples; the new
regression executions are separate evidence, retained outside Git.

## S12-F1: normalize before publishing

The former export path guard resolved its target for the namespace comparison,
but passed the original path to the publication helper. For an absent
`<database>-journal/../safe-export`, that helper first created the journal-named
directory. The final export could be correct while a later SQLite write failed.
The same namespace violation affected `-wal` and `-shm`. A database-file hash
alone did not detect the damage.

`export_execution` now checks the requested target with `lexists` (preserving
existing and dangling-link refusal), resolves its parent before any publication effect, checks the final name with
`lexists`, then resolves/checks the complete destination and database/sidecar
overlap. Inspecting the final name before following links preserves dangling
link refusal even when a nonexistent skipped parent obscures the original path.
The same resolved destination is passed to the unchanged no-replace publication
helper and returned in the successful response. A safe final destination reached
through `..` is supported; the skipped component is never created. Canonical
DB/sidecar targets and their descendants are refused with EXECUTION_OUTPUT.
The repair does not delete a user path, change SQLite pragmas, or alter the
shared review publication implementation.

`tests/test_stage12_1_export.py` contains five tests. Its actual CLI controls
cover ordinary raw-byte export, all three sidecar/`..` paths, a subsequent new
request after each export, database/sidecar/descendant collisions, existing
files/directories, a dangling symlink and a `..` alias of an existing directory.
Each witness observes the database and all reserved sidecar names before and
after export. Exported context BLOB and run TEXT bytes are compared with the
stored original bytes, independently of the exporter-returned hashes.

The unchanged 0.10.0 baseline ran five tests and reported four assertion
failures: three sidecar subcases and the existing-target alias. Ordinary export,
canonical collision and dangling-link controls passed. The corrected source
ran the identical file and passed all five tests. The baseline's journal and
WAL witnesses exported successfully but the next write exited 2; SHM still
allowed writing while violating the reserved namespace. All three corrected
witnesses preserve the namespace and allow the next write to exit 0.

## S12-F3: convert the expected UTC range overflow

The recorded API normalized timestamps before its transaction but converted
only ValueError and TypeError into EXECUTION_INPUT. A timezone offset could move
a legal local year outside datetime's UTC range and raise raw OverflowError.
The CLI consequently exited 1 with an empty stdout and traceback, confusing an
input failure with its documented financial non-match exit.

Only the recorded API's timestamp conversion exception tuple adds OverflowError.
It is converted to ExecutionError/EXECUTION_INPUT through the existing branch.
The shared financial model timestamp helper and all other financial commands
remain unchanged; no broad exception handler was added.

`tests/test_stage12_1_input.py` has seven tests. Four distinct API/CLI negatives
place each of `0001-01-01T00:00:00+23:59` and
`9999-12-31T23:59:59-23:59` in balance_at and knowledge_at. A valid execution is
stored first, then every old financial/context/execution row and payload is
compared before and after both rejected calls. The expected API class/reason,
CLI ERROR JSON/exit 2 and absence of traceback are explicit assertions.
Additional controls cover malformed syntax, normal COMPLETE/MATCHED, a literal
custody MISMATCH +1 retaining exit 1, and valid near-range timestamps with
appropriate early/late opening fixtures. Empty near-boundary fixtures produce
recorded financial non-match results, not input errors.

The unchanged baseline ran seven tests with precisely the four overflow
assertion failures. Syntax, near-boundary and financial-exit controls passed.
The corrected source passed the same seven-test file unchanged.

## Additional F1 boundary after the original same-file pair

A final read-through identified `unused/../dangling-link` as a separate boundary
inside the same refusal contract. The first path fix followed the final dangling
link to its missing referent after resolving the full path, so it could publish
there. A new two-test file, `test_stage12_1_export_alias.py`, was added after the
original RED/GREEN pair; the original five-test file and hash did not change.

The additional same-file RED/GREEN pair is `f1-alias/red-02` →
`f1-alias/green-01`: two tests, two failing alias subcases before the final fix,
then both tests passing. Existing live-link targets are a positive refusal
control. The earlier `red-01` also detected the defect but its direct import of
the parent TestCase caused unittest to discover five extra existing tests. That
attempt is retained; changing the import to a module reference removed duplicate
discovery before the final two-test RED/GREEN pair. No assertion was weakened.

The final repair resolves the parent and checks the terminal component before
following a possible final link. There is still no mkdir until all output and
namespace checks pass. The original five-test file was rerun because this
exporter code changed: `f1/green-02` passed all five with 0.10.1 metadata. This
also repeats the safe `..` publication, raw-byte equality and next-write controls.
